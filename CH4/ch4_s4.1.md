# Section 4.1: Control and Central Processing Units (ACtE0401)

## 📖 1. Introduction
The Central Processing Unit (CPU) is the brain of any computer system, responsible for executing instructions and coordinating all other components. This section dives deep into the architecture, control mechanisms, instruction execution, and performance enhancements of the CPU. For the NEC exam, understanding the intricacies of control units, addressing modes, and pipelining is essential, as these dictate how a processor behaves and performs.

## 💡 2. Basic Concept
At its core, a CPU fetches instructions from memory, decodes them to understand what needs to be done, fetches required operands, executes the operation, and stores the result back. The **Control Unit (CU)** is the conductor of this orchestra, sending timing and control signals to the Datapath (ALU and Registers).

> [!NOTE] Definition
> The **Central Processing Unit (CPU)** is the primary component of a computer that acts as its "brain." It contains the circuitry necessary to fetch, decode, and execute instructions from memory.

### Real-World Analogy
Think of the CPU as a restaurant kitchen.
*   **Memory**: The recipe book and pantry.
*   **Registers**: The small counter space where the chef works on immediate ingredients.
*   **ALU (Arithmetic Logic Unit)**: The chef doing the chopping and cooking (operations).
*   **Control Unit**: The head chef calling out orders and telling everyone when to start and stop their tasks.
*   **Pipelining**: An assembly line where one person chops, another cooks, and another plates, instead of one person doing it all sequentially.

---

## 3. Control Unit Design
The Control Unit coordinates all operations by generating control signals. There are two primary approaches to designing a control unit: Hardwired Control and Microprogrammed Control.

### 3.1 Hardwired Control Unit
In a hardwired control unit, control signals are generated by a complex network of logic gates, flip-flops, decoders, and other digital circuits. 

**Mathematical Formulation / State:**
The state of the control unit can be represented as a function of the Instruction Register (IR), timing signals (T), and status flags (F):
$$ C = f(IR, T, F) $$

**Characteristics:**
*   Very fast since it relies on hardware logic.
*   Complex and difficult to modify or debug.
*   Typically used in RISC architectures where instructions are simple and uniform.

### 3.2 Microprogrammed Control Unit
In a microprogrammed control unit, control signals are generated by reading a sequence of microinstructions from a special memory called **Control Memory**.

**Characteristics:**
*   Slower than hardwired control due to memory access time.
*   Highly flexible; changing the instruction set only requires changing the microprogram (firmware).
*   Typically used in CISC architectures.

### Hardwired vs. Microprogrammed Comparison

| Feature | Hardwired Control | Microprogrammed Control |
| :--- | :--- | :--- |
| **Speed** | Very fast | Slower (requires memory access) |
| **Flexibility** | Rigid, hard to modify | Flexible, easy to modify |
| **Design Complexity** | High (hardware wiring) | Low (software programming) |
| **Cost** | Cheaper for simple instructions | Cheaper for complex instruction sets |
| **Instruction Set Size** | Small, fixed (RISC) | Large, expandable (CISC) |

---

## 4. Control Memory
Control memory is a fast memory (usually ROM or PROM) within the CPU that stores microprograms. A **microprogram** is a sequence of **microinstructions**, and each microinstruction contains a **control word** that defines the state of all control signals for one clock cycle.

> [!NOTE] Definition
> A **Control Word** is a string of bits where each bit or group of bits corresponds to a specific control signal (e.g., read, write, ALU operation) needed during a clock cycle.

---

## 5. Address Sequencing
Address sequencing is the process of determining the address of the next microinstruction to be executed from the control memory. 

The next address can be determined by:
1.  **Incrementing** the current address (Current Address + 1).
2.  **Unconditional Branch**: Branching to a specified address always.
3.  **Conditional Branch**: Branching based on status flags (e.g., Zero flag, Carry flag).
4.  **Mapping**: Deriving the starting address of a microprogram routine directly from the opcode in the Instruction Register (IR).

```text
+-------------------+
| Instruction (IR)  |
+---------+---------+
          |
          v
+---------+---------+
| Mapping Logic     | ---> Starting Address
+---------+---------+
          |
          v
+---------+---------+
| Control Address   |<---+
| Register (CAR)    |    | Next Address
+---------+---------+    |
          |              |
          v              |
+---------+---------+    |
| Control Memory    |    |
+---------+---------+    |
          |              |
          v              |
+---------+---------+    |
| Microinstruction  |----+ (Branch logic)
| Register (MIR)    |
+---------+---------+
          |
          v
    Control Signals
```

## 6. Microinstruction Format
Microinstructions define how control signals are encoded.

### 6.1 Horizontal Microinstruction
*   Each bit directly controls one control signal.
*   **Format:** Long word length (e.g., 64-128 bits).
*   **Advantage:** Fast, highly parallel (many operations at once).
*   **Disadvantage:** Requires large control memory width.

### 6.2 Vertical Microinstruction
*   Control signals are grouped and encoded (e.g., using 3 bits to select 1 of 8 signals via a decoder).
*   **Format:** Short word length (e.g., 16-32 bits).
*   **Advantage:** Saves memory space.
*   **Disadvantage:** Slower (requires decoding time), less parallel capability.

---

## 7. CPU Structure and Function
The CPU primarily consists of the ALU, Control Unit, and a set of Registers.

### Register Organization
*   **General Purpose Registers (GPRs):** Used by the programmer to hold temporary data (e.g., R0, R1, R2).
*   **Special Purpose Registers:**
    *   **Program Counter (PC):** Holds the address of the *next* instruction to be executed.
    *   **Instruction Register (IR):** Holds the instruction currently being decoded and executed.
    *   **Memory Address Register (MAR):** Holds the address being accessed in memory.
    *   **Memory Data Register (MDR) / Memory Buffer Register (MBR):** Holds data being read from or written to memory.
    *   **Accumulator (AC):** Implicit register used in many arithmetic operations.
    *   **Status Register / Processor Status Word (PSW):** Contains condition flags (Zero, Carry, Sign, Overflow).

### Instruction Cycle
The execution of an instruction goes through several phases:
1.  **Fetch Cycle:**
    *   $MAR \leftarrow PC$
    *   $MDR \leftarrow M[MAR]$
    *   $IR \leftarrow MDR$
    *   $PC \leftarrow PC + 1$
2.  **Decode Cycle:** The CU interprets the opcode in the IR.
3.  **Execute Cycle:** The required operation is performed.
4.  **Write-Back Cycle (optional):** Result is written back to a register or memory.

---

## 8. Arithmetic and Logic Unit (ALU)
The ALU performs all computational tasks.
*   **Arithmetic Operations:** Addition, Subtraction, Increment, Decrement. (Multiplication/Division often done via repeated addition/subtraction or special hardware).
*   **Logical Operations:** AND, OR, XOR, NOT (bitwise operations).
*   **Shift Operations:**
    *   *Logical Shift:* Shifts bits, fills with 0s.
    *   *Arithmetic Shift:* Preserves the sign bit (MSB).
    *   *Rotate (Circular Shift):* Bits shifted out one end are shifted in the other end.

## 9. Instruction Formats
An instruction consists of an Opcode (what to do) and Operands (what to do it on). Architectures are often classified by the number of operands specified in an instruction.

Let's evaluate the expression $X = (A + B) * (C + D)$ using different formats.

### 9.1 Three-Address Instructions
Format: `Opcode Dest, Src1, Src2`
Example:
```assembly
ADD R1, A, B    ; R1 <- M[A] + M[B]
ADD R2, C, D    ; R2 <- M[C] + M[D]
MUL X, R1, R2   ; M[X] <- R1 * R2
```

### 9.2 Two-Address Instructions
Format: `Opcode Dest/Src1, Src2`
Example:
```assembly
MOV R1, A       ; R1 <- M[A]
ADD R1, B       ; R1 <- R1 + M[B]
MOV R2, C       ; R2 <- M[C]
ADD R2, D       ; R2 <- R2 + M[D]
MUL R1, R2      ; R1 <- R1 * R2
MOV X, R1       ; M[X] <- R1
```

### 9.3 One-Address Instructions (Accumulator Architecture)
Format: `Opcode Operand` (Implicit Accumulator)
Example:
```assembly
LOAD A          ; AC <- M[A]
ADD B           ; AC <- AC + M[B]
STORE T         ; M[T] <- AC (Temporary store)
LOAD C          ; AC <- M[C]
ADD D           ; AC <- AC + M[D]
MUL T           ; AC <- AC * M[T]
STORE X         ; M[X] <- AC
```

### 9.4 Zero-Address Instructions (Stack Architecture)
Format: `Opcode` (Operands implicitly on top of stack)
Example:
```assembly
PUSH A
PUSH B
ADD             ; Pops A, B, pushes A+B
PUSH C
PUSH D
ADD             ; Pops C, D, pushes C+D
MUL             ; Pops (A+B), (C+D), pushes result
POP X           ; M[X] <- result
```

## 10. Addressing Modes
Addressing modes specify *how* to calculate the **Effective Address (EA)** of an operand.

| Mode | Notation | EA Calculation | Description |
| :--- | :--- | :--- | :--- |
| **Immediate** | `#value` | Operand is part of instruction | Fast, no memory access for data. `MOV R1, #5` |
| **Direct** | `Address` | EA = Address | Address of operand is given. `LOAD 1000` |
| **Indirect** | `@Address` | EA = M[Address] | Memory holds the pointer to data. `LOAD @1000` |
| **Register** | `R1` | Operand is in R1 | Very fast. `ADD R1, R2` |
| **Register Indirect**| `(R1)` | EA = R1 | Register holds the pointer. `LOAD (R1)` |
| **Indexed** | `X(R1)` | EA = R1 + X | Good for arrays. `R1` is base, `X` is offset. |
| **Relative** | `X(PC)` | EA = PC + X | Good for branch targets relative to current code. |
| **Base Register** | `X(Base)`| EA = Base + X | Similar to indexed, used for memory relocation. |
| **Auto-increment** | `(R1)+` | EA = R1, then R1++ | Useful for stepping through arrays. |
| **Auto-decrement** | `-(R1)` | R1--, then EA = R1 | Useful for implementing stacks. |

> [!TIP] Exam Tip
> Always remember: **Effective Address (EA)** is the actual memory location where the operand is stored. If mode is Immediate, there is no EA. If mode is Register, the EA is the register itself.

## 11. Data Transfer and Manipulation
Instructions are grouped into categories:
*   **Data Transfer:** Move data between registers and memory. `MOV`, `LOAD`, `STORE`, `PUSH`, `POP`, `XCHG` (exchange).
*   **Data Manipulation:**
    *   *Arithmetic:* `ADD`, `SUB`, `MUL`, `DIV`, `INC`, `DEC`.
    *   *Logical:* `AND`, `OR`, `XOR`, `NOT`, `SHL`, `SHR`.
*   **Program Control:** Alter the flow of execution. `JMP` (unconditional), `JZ` (Jump if Zero), `CALL` (subroutine call), `RET` (return).

## 12. RISC vs. CISC
Two fundamentally different philosophies in CPU design.

| Characteristic | RISC (Reduced Instruction Set Computer) | CISC (Complex Instruction Set Computer) |
| :--- | :--- | :--- |
| **Instruction Size** | Fixed size (e.g., 32-bit) | Variable size |
| **Instruction Complexity** | Simple, single-cycle execution | Complex, multi-cycle execution |
| **Memory Access** | Load/Store architecture only | Many instructions can access memory |
| **Number of Registers** | Many general-purpose registers | Fewer general-purpose registers |
| **Control Unit** | Hardwired | Microprogrammed |
| **Pipelining** | Highly pipelined (easy due to uniform size) | Difficult to pipeline efficiently |
| **Code Size** | Larger (takes more simple instructions) | Smaller (complex instructions do more) |
| **Examples** | ARM, MIPS, RISC-V | x86 (Intel, AMD) |

## 13. Pipelining
Pipelining is a technique to increase CPU throughput by overlapping the execution of multiple instructions. It divides the instruction cycle into a sequence of distinct stages.

### Classic 5-Stage RISC Pipeline
1.  **IF (Instruction Fetch):** Fetch instruction from memory.
2.  **ID (Instruction Decode):** Decode instruction and read registers.
3.  **EX (Execute):** Perform ALU operation.
4.  **MEM (Memory Access):** Read or write data memory.
5.  **WB (Write Back):** Write result back to register.

```text
Clock:   1    2    3    4    5    6    7    8
Instr 1: IF   ID   EX   MEM  WB
Instr 2:      IF   ID   EX   MEM  WB
Instr 3:           IF   ID   EX   MEM  WB
Instr 4:                IF   ID   EX   MEM  WB
```

### 13.1 Performance and Speedup
*   $k$ = number of stages
*   $n$ = number of instructions
*   $t_p$ = clock cycle time of pipelined processor (usually max stage delay + latch delay)
*   $t_n$ = execution time for non-pipelined processor (usually $k \times t_p$)

Time to execute $n$ instructions in pipeline ($T_k$):
$$ T_k = (k + n - 1) \times t_p $$

**Speedup ($S$):**
$$ S = \frac{T_{non-pipeline}}{T_{pipeline}} = \frac{n \times k \times t_p}{(k + n - 1) \times t_p} $$
As $n \rightarrow \infty$, Speedup $S \rightarrow k$.
(Maximum theoretical speedup equals the number of stages).

### 13.2 Pipeline Hazards
Hazards prevent the next instruction from executing in its designated clock cycle.
1.  **Structural Hazards:** Hardware resource conflicts (e.g., memory port used by two instructions at once).
    *   *Solution:* Duplicate resources (e.g., separate Instruction and Data caches).
2.  **Data Hazards:** Instruction depends on the result of a previous instruction that is still in the pipeline.
    *   *Solution:* **Data Forwarding (Bypassing)**, stalling (inserting NOPs/bubbles).
3.  **Control Hazards (Branch Hazards):** Caused by branch instructions altering the PC, making fetched instructions invalid.
    *   *Solution:* Branch prediction, delayed branch, flushing the pipeline.

### Worked Example: Speedup Calculation
**Problem:** A 4-stage pipeline has stage delays of 10ns, 15ns, 12ns, and 14ns. The latch delay is 1ns. Calculate the time to execute 100 instructions and the theoretical maximum speedup over a non-pipelined system.

**Solution:**
1.  **Pipelined Clock Cycle ($t_p$):** 

$$t_p = \text{Max}(10, 15, 12, 14) + \text{Latch Delay} = 15 + 1 = 16 \text{ ns}$$
2.  **Time for 100 instructions ($T_k$):**

$$T_k = (k + n - 1) \times t_p = (4 + 100 - 1) \times 16 = 103 \times 16 = 1648 \text{ ns}$$
3.  **Non-pipelined Execution Time for 1 instr:** 

$$t_n = 10 + 15 + 12 + 14 = 51 \text{ ns}$$
    Total time = $100 \times 51 = 5100 \text{ ns}$
4.  **Actual Speedup:** 

$$S = \frac{5100}{1648} = 3.09$$
5.  **Max Theoretical Speedup:** 
    As $n \rightarrow \infty$, $S \rightarrow \frac{t_n}{t_p} = \frac{51}{16} = 3.18$

## 14. Parallel Processing (Flynn's Taxonomy)
Flynn classified computer architectures based on the number of concurrent instruction streams and data streams.

1.  **SISD (Single Instruction, Single Data):** Traditional sequential computer (uniprocessor). One instruction operates on one data item at a time.
2.  **SIMD (Single Instruction, Multiple Data):** One instruction is applied to multiple data items simultaneously. Used in Vector processors, GPUs, and multimedia extensions (e.g., MMX, SSE).
3.  **MISD (Multiple Instruction, Single Data):** Multiple instructions operate on a single data stream. Rare, mostly used in fault-tolerant systems (redundancy).
4.  **MIMD (Multiple Instruction, Multiple Data):** Multiple processors execute different instructions on different data. Multicore processors and distributed computing clusters fall here.

> [!IMPORTANT] Exam Focus
> Be prepared to identify real-world examples for Flynn's taxonomy. Modern desktop CPUs are MIMD, but they utilize SIMD instructions (like AVX) internally for media processing.

## ✏️ Practice Problems

1. **Question:** What is the effective address if the instruction is `LOAD 50(R2)` where R2 contains `2000`?
   *Answer:* Indexed addressing mode. EA = R2 + 50 = 2000 + 50 = 2050.

2. **Question:** Why do structural hazards occur in a pipeline?
   *Answer:* They occur when two different stages of the pipeline attempt to use the same hardware resource simultaneously (e.g., one instruction fetching from memory while another writes to memory).

3. **Question:** In microprogrammed control, what determines the length of a vertical microinstruction?
   *Answer:* The degree of encoding. Highly encoded control signals result in shorter (vertical) microinstructions, requiring external decoders.
