## Section Memory Management, File Systems and System Administration (AEiE0706)

## 📖 1. Introduction
Memory management, file systems, and system administration are critical pillars of operating system functionality. Memory management ensures efficient utilization of primary memory, file systems organize data on secondary storage, and system administration involves managing users and system operations. For the NEC exam, understanding virtual memory, paging, file mapping, and administration basics is essential.

## 💡 2. Basic Concept
The OS must manage the memory hierarchy. Main memory (RAM) is fast but volatile and limited; disks are slow but non-volatile and large. The file system abstracts disk storage into logical files and directories.

> [!NOTE] Definition
> **Logical Address**: Address generated by the CPU; also referred to as virtual address.
> **Physical Address**: Address seen by the memory unit (actual hardware RAM address).
> **Virtual Memory**: A technique that allows the execution of processes that are not completely in memory, giving the illusion of a very large main memory.

## 3. Memory Address and Swapping
- **Address Binding**: Mapping logical to physical addresses. Can happen at compile time, load time, or execution time (requires hardware support, Memory Management Unit - MMU).
- **Swapping**: A process can be swapped temporarily out of memory to a backing store, and then brought back into memory for continued execution. This allows the total physical memory space of processes to exceed actual physical memory.

### Managing Free Memory Space
- **Contiguous Allocation**: Each process occupies a single contiguous block of memory. Suffers from external fragmentation.
- **Paging**: Physical memory is divided into fixed-sized blocks called **frames**. Logical memory is divided into blocks of the same size called **pages**. Eliminates external fragmentation but suffers from internal fragmentation.

## 4. Virtual Memory Management and Demand Paging
Virtual memory is typically implemented via **Demand Paging**.
- **Demand Paging**: Bring a page into memory only when it is needed. Less I/O needed, less memory needed, faster response, more users.

### Page Fault
When a process tries to access a page that is not currently in physical memory, a **page fault** occurs.
1. Check internal table to see if access is valid.
2. If invalid, abort. If valid but not in memory, page it in.
3. Find a free frame.
4. Schedule disk operation to read the desired page into the frame.
5. Modify internal tables (page table) to indicate the page is now in memory.
6. Restart the instruction that caused the page fault.

### Page Replacement Algorithms
If there is no free frame, we must replace an existing page.
- **FIFO (First-In-First-Out)**: Replace the oldest page. Suffers from Belady's Anomaly (more frames can lead to more page faults).
- **Optimal (OPT)**: Replace the page that will not be used for the longest period of time. (Theoretical, cannot be implemented).
- **LRU (Least Recently Used)**: Replace the page that has not been used for the longest period of time. Good approximation of Optimal.

### Performance of Demand Paging
Effective Access Time (EAT):
$$EAT = (1 - p) \times \text{memory access} + p \times \text{page fault overhead}$$
Where $p$ is the page fault rate ($0 \le p \le 1$).

## 5. File Systems
A file is a named collection of related information recorded on secondary storage.
- **File attributes**: Name, Identifier, Type, Location, Size, Protection, Time/Date.
- **Directory**: A symbol table that translates file names into their directory entries.
- **File Paths**:
  - **Absolute Path**: Begins at the root and follows a path down to the specified file (e.g., `/usr/bin/gcc`).
  - **Relative Path**: Defines a path from the current working directory.

## 6. File System Implementation and Block Mapping
The disk is logically viewed as an array of blocks.

### Allocation Methods
How disk blocks are allocated for files:
1. **Contiguous Allocation**: Each file occupies a set of contiguous blocks. Simple, fast access, but suffers from external fragmentation and file growth issues.
2. **Linked Allocation**: Each file is a linked list of disk blocks. No external fragmentation, but slow random access (must traverse list). Pointers take up space.
   - **FAT (File Allocation Table)**: A variation where all pointers are stored in a table at the beginning of the volume.
3. **Indexed Allocation**: Brings all pointers together into one block (index block). Supports direct access, no external fragmentation, but index blocks waste space for small files.
   - In UNIX/Linux (inodes): Uses direct blocks, single indirect, double indirect, and triple indirect blocks to handle large files.

### Free Space Management
- Bit vector / Bit map (1 bit per block: 1 = free, 0 = allocated)
- Linked list (link together all free blocks)

## 7. System Administration
System administration involves configuring, managing, and maintaining a computer system.

### User Account Management
- Creating, modifying, and deleting user accounts and groups.
- Managing permissions and access control lists (ACLs) to ensure security.
- In Linux: `/etc/passwd` (user info), `/etc/shadow` (passwords), commands like `useradd`, `usermod`, `chmod`, `chown`.

### Start and Shutdown Procedures
- **Booting (Start)**: Power-on self-test (POST), Master Boot Record (MBR) loaded, Bootloader (e.g., GRUB) executes, Kernel loaded into memory, init/systemd process starts.
- **Shutdown**: Ensuring all processes are terminated gracefully, buffers are flushed to disk to prevent data corruption, and file systems are unmounted before powering off.

## 💡 Common Mistakes / Exam Tips

> [!WARNING]
> Paging eliminates *external* fragmentation, but there can still be *internal* fragmentation in the last page of a process.

> [!TIP]
> In page replacement questions, carefully trace the frame contents step-by-step. For LRU, always keep track of the most recently used time.

## 📝 Quick Reference / Formula Summary

> [!IMPORTANT]
> - **Page Number ($p$)**: Used as an index into a page table.
> - **Page Offset ($d$)**: Combined with base address to define physical address.
> - **Logical Address Space** $= 2^m$, **Page Size** $= 2^n$. Page number is $m-n$ bits, offset is $n$ bits.
> - **Inode max file size**: Sum of direct blocks + indirect capacity + double indirect capacity... $\times$ block size.

## ✏️ Practice Problems

1. Given a reference string: 7, 0, 1, 2, 0, 3, 0, 4, 2, 3 and 3 frames. How many page faults occur using FIFO?
   *Answer sketch: Trace memory: [7,-,-], [7,0,-], [7,0,1], [2,0,1], [2,0,1] (hit), [2,3,1], [2,3,0], [4,3,0], [4,2,0], [4,2,3]. Total page faults = 9.*

2. What is the difference between an absolute and a relative file path?
   *Answer sketch: Absolute starts from the root directory (/). Relative starts from the current working directory.*
